# QuotaMew｜因為一個太吃記憶體的工具，我決定自己做一個 macOS App

## 為什麼想做 QuotaMew？

其實一開始，我沒有特別打算要開發 macOS App。

那時候只是想找一款工具，可以讓我方便查看 Codex 的使用額度，不用每次都另外開啟介面確認還剩多少。

後來我下載了一款第三方監測工具，結果發現它在執行時占用了相當多的記憶體。我當時使用的是配備 24GB 統一記憶體的 MacBook Pro，卻還是遇到記憶體幾乎被占滿的情況。

當下我就在想：只是監測額度而已，真的需要消耗這麼多資源嗎？

雖然我沒有進一步確認那款軟體為什麼會出現這種情況，但也因為這次經驗，讓我開始想試著做一款自己的額度監測工具。

除了希望它夠輕量，我也想自己決定功能要怎麼設計。畢竟這是一個我每天都可能用到的東西，如果能按照自己的習慣調整，應該會方便很多。

於是就有了 QuotaMew。

## 第一次開發原生 macOS App

在 QuotaMew 之前，我比較熟悉的是網頁和其他應用程式開發，沒有真正做過一款完整的原生 macOS 工具。

所以這個專案對我來說，也是一次練習 Swift 和 SwiftUI 的機會。

另外，QuotaMew 的開發方式也比較特別。

因為平常會使用 Codex 這類 AI Coding Tools，有時候額度還沒用完就快到重設時間。我就想，既然還有額度，不如拿來做一些真正用得到的東西。

因此，這個專案的大部分程式碼其實是由 AI 協助完成的。我主要負責思考自己需要哪些功能、畫面應該怎麼呈現，以及下一步想改善什麼。

我沒有打算把它包裝成一個全部由自己手寫的專案。對我而言，這次比較像是在嘗試：能不能利用 AI 輔助開發，把一個平常生活中的小需求，慢慢做成可以使用的產品。

## Menu Bar 看起來簡單，其實很難安排

開發過程中，我花了不少時間思考的地方，反而是 Menu Bar 的 UI。

macOS 的選單列空間有限，而且不是只有 QuotaMew 會使用。使用者可能同時裝了很多其他工具，如果我的 App 占用太多寬度，就可能把其他項目擠掉。

我自己也會使用其他選單列工具，所以很清楚這件事其實會影響日常操作。

一開始在安排資訊時，我就在想：如果我是使用者，我打開電腦後真正想看到的是什麼？

對我來說，最重要的就是額度百分比。至於要看短期額度，還是每週額度，每個人的習慣可能不太一樣。

所以最後我決定讓使用者自己選擇。

目前 QuotaMew 提供三種 Menu Bar 顯示模式：

- 只顯示 5 小時額度的百分比。
- 只顯示 Weekly 額度的百分比。
- 同時顯示 5 小時與 Weekly 的百分比。

如果平常只關心 5 小時額度，就不需要一直把 Weekly 放在選單列上；如果兩個都想看，也可以一起顯示。

這樣的設計不算複雜，但我覺得很實用。

目前 Menu Bar 上仍然有 QuotaMew 的 Icon。其實我也在考慮未來把它移除或改成可選，因為 Icon 本身也會占用一些空間。

我希望最後的呈現方式可以再精簡一點，盡量不要影響其他工具。

## Codex 額度是怎麼取得的？

QuotaMew 目前主要整合 Codex。

它不是直接去讀取使用者的認證檔案，而是透過本機的 codex app-server，利用 stdio 通訊取得額度資訊。

取得資料後，再整理成 App 需要的格式，像是 5 小時額度、Weekly 額度、剩餘百分比，以及重設時間等。

我選擇沿用 Codex 現有的本機介面，不必為了顯示額度，再額外設計一套認證流程。

這個部分也讓我接觸到一種不同於一般網頁 API 的整合方式：透過本機程序之間的通訊取得資料，再呈現在原生 macOS 介面上。

## 有些功能寫出來了，但還不能說已經支援

開發時還有兩件事情比較麻煩。

第一個是 Claude Code。

我當時沒有可以用來完整測試的付費帳號，因此即使已經有部分相關程式碼，也沒有辦法實際確認所有整合流程都正常。

所以目前 Claude Code 相關功能仍然屬於實驗性、尚未完整驗證的狀態。

我不希望只是因為程式碼存在，就把功能標成正式支援。

第二個是 Apple Developer Program。

由於當時沒有加入付費開發者計畫，正式的程式碼簽署、公證，以及對外分發流程還有一些無法完整驗證的部分。

這些都會是未來要繼續處理的工作。

## 記憶體使用量如何？

因為當初就是受到其他監測工具記憶體消耗問題的影響，所以在開發 QuotaMew 時，我也會特別注意它吃掉多少系統資源。

以目前我自己的使用觀察來看，大致是這樣：

| 運作狀態 | 約略記憶體用量 |
| --- | --- |
| 背景閒置 | 12 MB |
| 執行刷新或更新 | 50 MB |

這些數字只是開發期間的初步觀察，還沒有做完整的效能基準測試，也不能直接拿來證明 QuotaMew 比其他監測工具更省記憶體。

不過至少就目前的使用情況來說，這樣的資源占用符合我一開始希望它盡量輕量的方向。

未來如果有機會，我也想再針對長時間背景執行、持續刷新，以及不同 Mac 環境進行比較完整的測試。

## 接下來想做什麼？

目前 QuotaMew 還是以 Codex 為主要支援對象，但我有不少想加入的功能。

除了繼續調整 Menu Bar 的寬度，也希望未來能支援更多 AI Coding Tools。

如果後續真的支援多個工具，我也想研究能不能讓不同工具的額度以獨立的 Menu Bar 項目顯示，而不是全部擠在同一個位置。

當然，這些目前都還只是規劃，實際要怎麼做，還需要再研究與測試。

## 最後

QuotaMew 一開始真的只是我想自己試著做做看的小工具。

剛好遇到其他軟體資源消耗太高的問題，又想練習原生 macOS 開發，手上也有可以利用的 AI 額度，就決定把這幾件事結合起來。

目前它還有不少可以改善的地方，但至少已經慢慢朝我想要的方向發展。

對我來說，最重要的還是讓它夠直覺、夠輕量，而且真的能在每天使用 Mac 的時候派上用場。
